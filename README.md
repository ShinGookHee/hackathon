# TripMate: 여행 일정 변경 대응 Assistant

비 예보, 교통 지연, 시설 공지가 겹친 날 **무엇을 유지하고 무엇을 바꿀지**를 근거와 함께 보여주는 웹 앱과 CLI입니다.

## 1. 문제 정의

**사용자의 핵심 문제**
친구 4명이 짜 둔 하루 일정(미술관 → 식당 → 한강공원 → 전망대 → 공연)이 있습니다. 당일 아침 강수 예보가 강해지고(D04), 오후 지하철 지연 안내(D06)와 시설 공지(D05)가 추가됐습니다. 정보마다 성격이 다릅니다. 공연 입장 마감처럼 **확정된 조건**이 있고, 강수확률이나 지연시간처럼 **바뀔 수 있는 예측**이 있습니다. 그래서 일행은 "원래 일정대로 가도 되는지, 바꾼다면 어떻게 바꿔야 하는지"를 판단하기 어렵습니다.

**가장 먼저 해결할 것**
환불이 안 되는 공연(18:40 입장 마감)과 예약을 확실히 지키는 것이 우선입니다. 그 조건 안에서 비와 지연의 불확실성을 감안해 야외 일정과 이동수단을 조정합니다.

**프로그램이 제공하는 결과**
- **추천 일정:** 이동이 빠를 때와 늦을 때의 시간 범위로 보여줍니다.
- **추천 이유:** 각 항목에 근거 태그(`D01`~`D08`, `입력값`, `가정`)를 붙입니다.
- **불확실성:** 예보·추정을 확정 사실로 쓰지 않고, 무엇이 불확실한지 명시합니다.
- **사용자가 확인할 항목:** 시각과 함께 보여줍니다. 예: 09:30 환불 기한, 출발 전 예보 재확인.
- **고정 조건과 변경 가능 조건 구분표**, **후보 6개 비교표**를 함께 보여줍니다.

**동작 방식 (하드코딩 없음)**
1. `data/scenario_default.json`에 D01~D08을 구조화했습니다. 각 값에 출처(`sources`)를 달았습니다.
2. 엔진(`tripmate/engine.py`)이 후보 일정을 조합으로 만듭니다. 한강 처리 방식 3가지(원안 체류, 30분 축소, 실내 카페 대체)와 지연 구간 이동수단 2가지(대중교통, 택시)를 곱해 6개가 나옵니다.
3. 각 후보를 **가장 빠른 이동**과 **가장 느린 이동** 두 경우로 시뮬레이션합니다.
   - 확정 조건(예약 시간, 공연 입장 마감)은 **최악의 경우**를 기준으로 판정합니다.
   - 지하철 지연은 이동 구간 [출발, 최악 도착]이 점검 시간대와 조금이라도 겹치면 더합니다.
   - 다음 일정이 확정 조건이면, 체류 시간을 자동으로 줄여 제때 출발하게 합니다.
4. 벌점으로 후보를 비교합니다. 벌점 항목은 확정 조건 위반 위험, 공연 입장 여유 부족, 강수 예보 시간대의 야외 체류(강수확률 반영), 일행 선호 위반, 택시 횟수와 예산 초과입니다. 벌점이 가장 낮은 안을 추천합니다. 확정 조건을 모두 지키는 안이 없으면 위반 개수 → 최악 기준 초과 시간 합계가 가장 작은 안을 "위반이 가장 적은 안"으로 보여주고, 위반 조건과 초과 분을 함께 표시합니다.
5. 추천 이유는 추천안과 비교 대상 안의 **감점 항목 차이**로 만듭니다. 한강 판단은 같은 이동수단의 원안과, 이동수단 판단은 같은 한강 처리의 다른 이동수단과 비교합니다. 불확실성과 확인 항목도 계산 결과로 문장을 생성합니다. 입력값이 기본 자료와 다르면 근거에 `입력값` 태그가 붙습니다.
6. **역할 분담: AI는 자연어 해석과 요약, 판단은 규칙 엔진.** 추천·판정은 항상 엔진이 계산하고, AI는 엔진 앞뒤에서만 씁니다.
   - **상황 업데이트(앞):** 사용자가 "지하철이 40~50분 늦는대"처럼 쓰면 Claude가 이를 입력값 변경안으로 바꿉니다. 바꿀 수 있는 항목은 왼쪽 폼에 있는 항목(`tripmate/interpret.py`의 화이트리스트)뿐입니다. 서버가 경로·형식·범위·시작≤끝·시나리오 검증을 다시 하고, 통과하지 못한 제안은 "반영하지 못한 내용"으로 돌립니다. 사용자가 체크해서 확인한 값만 폼에 반영해 재계획합니다. 일정 삭제처럼 값으로 표현할 수 없는 요청과, 문장 안의 지시문("규칙을 무시해" 등)은 반영하지 않습니다.
   - **AI 브리핑(뒤):** Claude가 엔진 결과를 4~6문장으로 요약해 추천안 박스 바로 아래에 "AI 브리핑"으로 보여줍니다. 엔진 판정이 먼저, AI 설명이 그다음에 오도록 배치했습니다. 근거 태그가 없거나 자료에 없는 태그를 쓰면 브리핑을 버립니다.
   - 키가 없거나 호출이 실패하면 두 기능 모두 안내 문구만 보여주고, 규칙 기반 결과와 폼 입력은 그대로 동작합니다.

## 2. 실행·사용 방법

### 필요한 프로그램
- **Python 3.15.0**(Windows 11)에서 실행해 확인했습니다. 다른 버전에서는 실행해 보지 않았습니다.
- 기본 기능에는 **설치할 패키지가 없습니다.** 표준 라이브러리만 사용합니다.

### 웹 앱 실행
```bash
git clone https://github.com/ShinGookHee/hackathon.git
cd hackathon
python server.py
```
브라우저에서 http://localhost:8000 을 엽니다. 포트를 바꾸려면 환경변수 `PORT`를 설정합니다(예: `PORT=9000`).

### 웹 앱 사용 순서
1. 페이지를 열면 기본 자료(D01~D08)로 계산한 결과가 바로 표시됩니다.
2. 왼쪽 입력 폼에서 값을 바꿉니다. 강수확률, 지하철 추가 지연, 점검 시간대, 공연 입장 마감, 예산, 판단 시각 등을 바꿀 수 있습니다. 기본값과 달라진 칸은 회색 배경과 빨간 점으로 표시됩니다. 시간은 24시간제 `HH:MM`으로 입력합니다(`930`, `9:30`은 `09:30`으로 자동 변환). 형식이 틀리면 칸이 빨간 테두리로 바뀌고, 재계획을 눌러도 서버에 보내지 않고 오류 메시지를 보여줍니다. 이때 화면의 결과는 흐려지고 "이전 입력 기준" 안내가 붙습니다. **판단 시각**은 미술관 환불 기한(09:30)이 지났는지 판단하는 데만 씁니다.
3. 상단의 **재계획 ▶** 버튼을 누르면 결과가 다시 계산됩니다.
4. 결과 화면 구성은 다음과 같습니다.
   - 가운데 위: 추천안 박스. 박스 안에 엔진 판정 다음으로 **한눈에 보기**가 붙습니다.
     - ✔ 유지: 원안과 같은 일정 / ↻ 변경: 원안 대비 바뀐 점(축소·대체·이동수단) / ☐ 지금 확인: 확인 항목 중 첫 번째
     - ⇄ 직전 대비: 직전 재계획과 비교해 바뀐 입력값과 추천 변화(예: `지하철 추가 지연 (분) 20~30→40~50 ⇒ 추천 E → C`)
   - 그 바로 아래 **AI 브리핑**(키가 있을 때 자동 표시). 처음 3줄만 보이고 **더 보기**로 펼칩니다.
   - 가운데: 추천 일정 타임라인. 🔒는 고정, 점선 ◌은 변경 가능, ⚠는 불확실 정보입니다.
   - 아래: 고정·변경 가능 조건표(항상 펼침). 후보 비교표는 "후보 6개 비교 · 추천 E 1위 · 원안 A 6위"처럼 요약 줄만 보이게 접혀 있고, 누르면 펼쳐집니다.
   - 오른쪽: 추천 이유, 불확실성, 확인할 항목. 각각 3개까지 보이고 나머지는 **더 보기 (+N)**로 펼칩니다. 선택한 안의 감점 내역은 접혀 있습니다.
   - 왼쪽 아래 **세부 설정**(일행 선호·가정값 6개)과 **전체 시나리오 JSON**은 접혀 있습니다. 세부 설정은 기본값과 다른 값이나 입력 오류가 있으면 자동으로 펼쳐집니다.
5. 근거 칩(`D04` 등)에 마우스를 올리면 해당 자료의 원문 요약이 나옵니다.
6. 가운데 위쪽 탭(A~F)을 누르면 다른 후보의 일정과 감점 내역을 볼 수 있습니다. 후보 이름은 입력이 바뀌어도 고정이고, 추천안에는 ★가 붙습니다.

   | 안 | 한강공원 P | 한강→전망대 이동 |
   | --- | --- | --- |
   | A (원안) | 원안 90분 | 대중교통 |
   | B | 원안 90분 | 택시 |
   | C | 30분으로 축소 | 대중교통 |
   | D | 30분으로 축소 | 택시 |
   | E | 실내 카페로 대체 | 대중교통 |
   | F | 실내 카페로 대체 | 택시 |

   지연 구간(`disruptions`)을 비우는 등 JSON 구조를 바꾸면 후보 수와 이름이 달라질 수 있습니다.
7. 폼에 없는 값은 왼쪽 아래 **전체 시나리오 JSON (고급)**에서 직접 수정하고 **JSON 적용**을 누릅니다. 이동시간, 체류시간 등이 여기에 해당합니다. `data/samples/*.json` 파일을 **파일 업로드**로 불러올 수도 있습니다.
8. **기본값 복원**을 누르면 D01~D08 원래 값으로 돌아갑니다.

### 상황 업데이트 (AI 해석, 선택)
1. 왼쪽 패널 맨 위 **상황 업데이트** 칸에 지금 상황을 씁니다. 예: `지하철이 40~50분 늦는대`, `비가 그치고 하늘이 맑아졌어`, `공연 입장 마감이 18:20으로 당겨졌대`.
2. **AI로 해석**을 누르면 표가 나옵니다: 항목 | 현재값 → 제안값 | 근거 문장 | 적용.
   - 사용자가 숫자를 말하지 않아 AI가 값을 짐작한 항목에는 **⚠ 추정**이 붙고, 기본으로 체크가 해제되어 있습니다.
   - 반영할 수 없는 내용(예: `미술관 취소해 줘`)은 **반영하지 못한 내용**에 이유와 함께 나옵니다.
3. 반영할 항목만 체크하고 **적용 후 재계획**을 누릅니다. 체크한 값이 왼쪽 폼에 들어가고 재계획됩니다. 바뀐 값은 결과에서 `입력값` 근거로 표시됩니다.
4. 키가 없으면 "AI 해석을 사용할 수 없습니다. 왼쪽 폼에서 직접 수정해 주세요."가 나옵니다.

### 폴더 구조
```
hackathon/
├── server.py                  # 웹 서버 (python server.py)
├── tripmate/
│   ├── engine.py              # 후보 생성, 시뮬레이션, 벌점, 이유·불확실성·확인 항목 생성
│   ├── scenario.py            # 시나리오 로드, --set 덮어쓰기, 입력 검증
│   ├── cli.py                 # CLI (python -m tripmate.cli)
│   ├── interpret.py           # 선택: 상황 업데이트 해석 (화이트리스트, 서버 측 재검증)
│   ├── llm.py                 # 선택: Claude 요약 (.env 사용)
│   └── llm_check.py           # 선택: Claude 연결 점검 (python -m tripmate.llm_check)
├── static/index.html          # 웹 UI (외부 CDN 없음)
├── data/
│   ├── scenario_default.json  # D01~D08 구조화 자료
│   └── samples/*.json         # 변형 입력 4종
├── requirements.txt           # 기본 실행: 설치 패키지 없음
├── requirements-llm.txt       # 선택: anthropic
└── .env.example               # 선택: AI 브리핑·상황 업데이트 환경변수 예시
```

### CLI 실행 (선택)
```bash
python -m tripmate.cli                                    # 기본 자료
python -m tripmate.cli --input data/samples/heavy_delay.json
python -m tripmate.cli --set weather.rain_prob=30         # 값 하나만 바꾸기
python -m tripmate.cli --set "disruptions.0.transit_extra=[50,60]" --json   # JSON 출력
```
Windows 콘솔에서 한글이 깨지면 먼저 `set PYTHONIOENCODING=utf-8`(cmd) 또는 `$env:PYTHONIOENCODING="utf-8"`(PowerShell)를 실행합니다.

### 샘플 입력 (`data/samples/`)
| 파일 | 기본 자료에서 바꾼 값 |
| --- | --- |
| `low_rain.json` | 강수확률 80% → 20%, 풍속 9 → 4m/s |
| `heavy_delay.json` | 지하철 추가 지연 20~30분 → 50~60분, 점검 중 택시 20~35분 → 30~45분 |
| `tight_deadline.json` | 공연 입장 마감 18:40 → 18:10 |
| `clear_day.json` | 강수확률 10%, 풍속 3m/s, 지하철 추가 지연 0분 |

### AI 브리핑·상황 업데이트 (선택)
AI 브리핑과 상황 업데이트(AI 해석)는 선택 기능이며 같은 설정을 씁니다. 없어도 모든 핵심 기능이 동작합니다.
```bash
pip install -r requirements-llm.txt      # anthropic SDK
cp .env.example .env                     # Windows: copy .env.example .env
```
`.env`에 다음 값을 넣습니다. `.env`는 `.gitignore`에 포함되어 저장소에 올라가지 않습니다.

| 환경변수 | 필수 | 설명 |
| --- | --- | --- |
| `ANTHROPIC_API_KEY` | 예 | Claude API 키 |
| `ANTHROPIC_BASE_URL` | 아니오 | 기본 API가 아닌 주소를 쓸 때만 |
| `ANTHROPIC_MODEL` | 아니오 | 비우면 `claude-opus-5-5` |

키가 설정되어 있으면 체크하지 않아도 **AI 브리핑**이 자동으로 켜집니다. 규칙 기반 결과가 먼저 표시되고, AI 브리핑은 추천안 박스 바로 아래에 "생성 중" 자리를 잡았다가 몇 초 뒤 채워집니다. 상단 "AI 브리핑" 체크를 끄면 숨겨집니다. 키나 패키지가 없으면 같은 자리에 "AI 브리핑을 사용할 수 없습니다" 한 줄이 나오고, 결과는 규칙 엔진만으로 그대로 표시됩니다. CLI에서는 `--llm` 옵션을 붙입니다.

## 3. 검증 결과

아래는 2026-10-20에 개발 PC(Windows 11, Python 3.15.0)에서 **실제로 실행한** 결과입니다.

| # | 입력 | 예상 결과 | 실제 결과 |

## 4. 구현 범위

**완성한 기능**
- D01~D08을 구조화한 시나리오 JSON. 모든 값에 출처를 달았습니다.
- 최선·최악 이동시간 두 경우 시뮬레이션. 확정 조건은 최악의 경우로 판정합니다.
- 고정 조건과 변경 가능 조건 구분표.
- 후보 6개 자동 생성, 벌점 비교, 추천.
- 추천 이유, 불확실성, 확인할 항목 생성. 모두 근거 태그 포함이며, 사용자가 바꾼 값은 `입력값`으로 표시합니다.
- 웹 UI: 입력 폼, JSON 편집·업로드·다운로드, 타임라인, 후보 탭, 근거 원문 툴팁.
- CLI: `--input`, `--set`, `--json`, `--llm`.
- 선택 기능인 Claude 요약. 근거 태그 검증과 실패 시 대체 동작이 들어 있습니다.
- 선택 기능인 자연어 상황 업데이트. Claude가 해석하고, 서버가 화이트리스트·형식·범위를 다시 검증하며, 사용자가 확인한 값만 적용합니다.

**미완성·제외한 기능**
- 채팅형 대화, 지도, 실시간 날씨·교통 API 연동, 로그인.
- 일정 순서 자체의 재배치. 예: 전망대를 한강보다 먼저 가는 순서. 장소 순서는 입력 JSON의 `stops` 순서를 따릅니다.
- 미술관·식당 같은 고정 일정을 취소하는 후보. 고정 일정은 항상 유지합니다.

**알려진 한계**
- 택시 요금(1회 15,000~25,000원, 4명이 1대)과 대중교통 요금(1인 1,500원)은 자료에 없어 **가정한 값**입니다. 화면에 `가정`으로 표시되며 폼에서 바꿀 수 있습니다.
- 다음 값도 가정입니다: 식당 체류 90분, 실내 카페 체류 60분, 비 판단 기준 강수확률 60%, 데크 폐쇄 위험 풍속 8m/s, 공연 입장 목표 여유 20분.
- 벌점 가중치는 엔진 코드의 상수입니다. 순위가 비슷한 후보는 가중치에 따라 뒤바뀔 수 있으므로 비교표의 벌점 차이를 함께 보는 것이 좋습니다.
- 공연 종료 후 서울역(21:30 출발)까지의 이동은 자료가 없어 계산하지 않습니다. 확인 항목으로만 안내합니다.
- **판단 시각**은 환불 기한 판단에만 씁니다. 판단 시각 이후부터 남은 일정을 다시 계획하는 기능은 없습니다(지난 일정을 완료로 처리하지 않음).
- 지하철 지연 여부는 평상시 최악 이동시간 기준으로 점검 시간대와 겹치는지 봅니다. 그래서 빠른 이동 경우에도 지연이 들어갈 수 있습니다(보수적 판단).
- 모든 후보가 전망대를 들릅니다(체류 0분까지만 줄임). 전망대를 빼는 후보는 없어서, 마감이 아주 이른 경우 "위반이 가장 적은 안"도 전망대 이동을 포함합니다.
- 강수 시간대 판단은 시간대 겹침과 강수확률만 사용합니다. 강수량이나 강도는 자료에 없어 반영하지 않습니다.
- 지연 구간(`disruptions`)이 있는 구간에만 택시를 후보로 넣습니다.
- 상황 업데이트는 왼쪽 폼에 있는 항목만 바꿀 수 있습니다. 이동시간 자체, 장소 추가·삭제, 순서 변경은 해석하지 않습니다.
- 상황 업데이트의 "추정" 값(예: "비가 그쳤어" → 강수확률 10%)은 AI가 짐작한 값입니다. 같은 문장이라도 실행마다 다른 값이 나올 수 있어 기본으로 체크 해제해 두었습니다.
- 검증 22~26의 AI 해석 결과는 각 문장을 한 번씩 실행한 결과입니다. LLM 응답은 실행마다 조금씩 다를 수 있습니다.
